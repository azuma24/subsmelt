# Convert batches

The Convert page uploads each selected subtitle exactly once to `POST /api/convert/batches`. The server writes the bounded upload to its persistent `DATA_DIR/convert-batches` directory (override with `CONVERT_BATCH_DIR`), returns a random batch ID, and processes files serially independently of the HTTP connection. The UI lists retained jobs from `GET /api/convert/batches`, polls `GET /api/convert/batches/:id` after reload, and retrieves completed outputs from `GET /api/convert/batches/:id/files/:index`. The latest selected ID is saved in localStorage for convenience, but history is recoverable without it. A newly submitted batch automatically downloads when completed while the same tab remains open; returning to a historical batch does not auto-download. The existing synchronous `POST /api/convert` remains available for legacy clients. ZIP creation is on demand in the browser from retrieved outputs; no output bytes live in UI state between visits.

The store accepts at most 10 files of 1 MiB UTF-8 each, at most 10 MiB total and 20 retained batches. Converted outputs are capped at 1 MiB each. A worker isolates each file's failure; after a process restart, pending/working files are retried while completed files are not. A crash *during* a file can cause that file's LLM request to run again. Settings/connection changes between upload and execution affect translation because credentials are not copied into the job record.

Inputs are deleted only after their completion/error status is durably saved; outputs plus status are deleted 24 hours after completion. Active batches are never age-expired, but the 20-job capacity may reject new uploads until work completes and retention expires. Cleanup runs on startup and every minute. The directory must be on persistent storage to survive a server/container restart; backups of this directory contain private subtitle text. Keep `DATA_DIR` and `CONVERT_BATCH_DIR` outside version control and protect the parent volume. Existing installations with retained jobs in `CONFIG_DIR/convert-batches` must move that directory into `DATA_DIR/convert-batches` before upgrading if they need to retain those results. Files and job directories are created with owner-only permissions. The historical listing exposes retained filenames and states, and batch IDs act as bearer capabilities for output access; do not expose this API publicly or to untrusted users without authentication.
